\subsection*{Task 1.1 -- Data Augmentation}

The \texttt{vanilla} branch of \texttt{get\_data\_loader} composes the
following pipeline (in order): resize to a slightly larger canvas, take a
random square crop back to \texttt{opts.image\_size}, randomly flip

so the output range matches the generator's \texttt{tanh}.

\begin{lstlisting}
load_size = int(1.1 * opts.image_size)
osize = [load_size, load_size]
train_transform = transforms.Compose([
    transforms.Resize(osize, Image.BICUBIC),
    transforms.RandomCrop(opts.image_size),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),
    transforms.Normalize((0.5, 0.5, 0.5), (0.5, 0.5, 0.5)),
])
\end{lstlisting}

\subsection*{Task 1.2a -- Padding Derivation}

For a 2-D convolution with input spatial size $H_{\text{in}}$, kernel
size $K$, stride $S$, and padding $P$, the output size is
%
\begin{equation}
    H_{\text{out}}
    \;=\;
    \left\lfloor
    \frac{H_{\text{in}} + 2P - K}{S}
    \right\rfloor + 1.
    \label{eq:conv-out}
\end{equation}
%
The discriminator's first four convolutions must downsample by exactly a
factor of two, i.e. $H_{\text{out}} = H_{\text{in}}/2$, with the prescribed
$K = 4$ and $S = 2$. Substituting into~\eqref{eq:conv-out} (and noting
that $H_{\text{in}}$ is even so the floor is exact):
%
\begin{align*}
    \frac{H_{\text{in}}}{2}
        &= \frac{H_{\text{in}} + 2P - 4}{2} + 1 \\[2pt]
    H_{\text{in}}
        &= H_{\text{in}} + 2P - 4 + 2 \\[2pt]
    0   &= 2P - 2 \\[2pt]
    \boxed{P = 1.}
\end{align*}
%
Sanity check on layer~1: $H_{\text{in}}=64$ gives
$\lfloor (64 + 2 - 4)/2 \rfloor + 1 = 31 + 1 = 32$, halving the spatial
extent as required. The same holds for the remaining three downsampling
layers.

\subsection*{Task 1.3 -- DCGenerator}

The generator is the discriminator's mirror image: it takes a noise
vector $z\!\in\!\mathbb{R}^{\,\text{noise\_size}}$ shaped as
$(\text{noise\_size}, 1, 1)$ and progressively upsamples it to a
$3\!\times\!64\!\times\!64$ image. Layers~2--5 follow the canonical
``upsample then convolve'' recipe: nearest-neighbour upsampling with
\verb|scale_factor=2| doubles the spatial extent, and a
$K\!=\!3, S\!=\!1, P\!=\!1$ convolution preserves it (verifying with
\eqref{eq:conv-out}: $\lfloor(2H_{\text{in}}+2-3)/1\rfloor+1 = 2H_{\text{in}}$).
This factored design avoids the well-known checkerboard artifacts that
plain transposed convolutions can produce.

\paragraph{First layer: $1\!\times\!1 \to 4\!\times\!4$ with no upsample.}
Following the assignment hint, \verb|up_conv1| is built with the
\verb|conv()| helper (i.e.\ a plain \verb|Conv2d| with InstanceNorm and
ReLU, \emph{no} \verb|Upsample| stage at all) and lets the convolution
itself expand the spatial extent. From~\eqref{eq:conv-out} with
$H_{\text{in}}=1$, $H_{\text{out}}=4$, $S=1$:
\begin{align*}
    4 &= (1 + 2P - K) + 1 \\[2pt]
    \Rightarrow\; 2P - K &= 2.
\end{align*}
Choosing $K=4$ gives $\boxed{P=3}$. Sanity check: padding the
$1\!\times\!1$ input on every side with three zeros yields a
$7\!\times\!7$ tensor; sliding a $4\!\times\!4$ kernel with stride~1
produces $\lfloor (7-4)/1 \rfloor + 1 = 4$ output positions, as required.

\subsection*{Task 1.4 -- DCGAN Training Loop}

The training loop alternates one discriminator step and one generator
step per minibatch, both with the least-squares loss from
Algorithm~1 of the assignment.

\paragraph{Discriminator update.} Given $m$ real images $x$ and $m$
generator samples $\tilde{x}=G(z)$ (with fresh noise $z\!\sim\!\mathcal{U}[-1,1]^{\,d}$),
\begin{align*}
    J^{(D)}_{\text{real}} &= \frac{1}{m}\sum_{i=1}^{m}\bigl(D(x^{(i)}) - 1\bigr)^{2}, \\
    J^{(D)}_{\text{fake}} &= \frac{1}{m}\sum_{i=1}^{m} D\bigl(G(z^{(i)})\bigr)^{2}, \\
    J^{(D)}                  &= \tfrac{1}{2}\bigl(J^{(D)}_{\text{real}} + J^{(D)}_{\text{fake}}\bigr).
\end{align*}
The fake batch is detached (\verb|fake_images.detach()|) before the
discriminator forward pass so the discriminator gradients do not leak
into $G$'s parameters.

\paragraph{Generator update.} A \emph{fresh} noise batch $z'$ is drawn,
$\tilde{x}'=G(z')$ is generated, and
\[
    J^{(G)} \;=\; \frac{1}{m}\sum_{i=1}^{m}\bigl(D(G(z'^{(i)})) - 1\bigr)^{2}.
\]
Here gradients must flow through both $D$ and $G$, so no detach is used
and only the generator parameters are stepped. Drawing new noise (rather
than reusing the discriminator's batch) is what the pseudocode
prescribes and avoids any subtle bias from over-fitting to the same
samples in the same iteration.

\subsection*{Task 1.5 -- Differentiable Augmentation}

\verb|prepare_images| is the hook the training loop calls on every batch
of images before they reach the discriminator (both real and fake). With
\verb|--use_diffaug| it applies the DiffAugment policy
\verb|'color,translation,cutout'|; otherwise it is a pass-through:

\begin{lstlisting}
def prepare_images(images, opts):
    if opts.use_diffaug:
        return DiffAugment(images, policy=policy)
    return images
\end{lstlisting}

\paragraph{Why this is different from Task 1.1.} Standard data
augmentation (Task 1.1) lives in the dataloader, so it only touches
\emph{real} images and is non-differentiable -- no gradient ever flows
through it. DiffAugment is applied \emph{inside} the training loop to
both real and fake images, and every transformation it uses
(brightness/colour jitter, translation, cutout) is implemented with
differentiable PyTorch ops. As a result, when the generator's loss is
back-propagated through the discriminator, gradients continue to flow
through the augmentation into $G$. This is what the original
DiffAugment paper identifies as essential: if only $D$ saw augmented
images while $G$ was trained against the un-augmented version, the two
networks would be optimising different distributions and training would
degrade.

\subsection*{Task 1.6 -- W\&B Logging}

Logging is wired up at four sites in \verb|vanilla_gan.py|:

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Run init} (top of \verb|training_loop|, after the
          fixed-noise vector is created):
\begin{lstlisting}
wandb.init(
    project='assignment1-dcgan',
    name=f'dcgan_diffaug={opts.use_diffaug}',
    config=vars(opts),
)
\end{lstlisting}
          The run name carries the boolean \verb|opts.use_diffaug| so
          the with/without comparison is immediate in the dashboard,
          and \verb|config=vars(opts)| serialises every command-line
          argument.

    \item \textbf{Scalar losses} every \verb|opts.log_step| iterations:
          \verb|D/real_loss|, \verb|D/fake_loss|, \verb|D/total_loss|,
          \verb|G/loss|, all keyed by \verb|step=iteration|. The
          \verb|D/| and \verb|G/| prefixes group the four panels under
          ``Discriminator'' and ``Generator'' headers in W\&B.

    \item \textbf{Image grid} inside \verb|save_samples| (every
          \verb|opts.sample_every| iterations) using
          \verb|wandb.Image(grid, caption=f'iter {iteration}')|. The
          grid is the same uint8 image that is also written to disk, so
          the dashboard sample matches the local artefact bit-for-bit.

    \item \textbf{Run finish}: \verb|wandb.finish()| after the training
          loop returns.
\end{enumerate}

Both \verb|wandb.log| calls pass \verb|step=iteration|, so the
loss-curve panel and the image panel share a common monotone time axis
that lets the visual quality at iteration $k$ be read off against the
loss values at the same $k$.
